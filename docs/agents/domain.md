# Domain docs

## Layout

This repo uses a single-context layout.

- `GLOSSARY.md` at the repo root defines domain terms.
- `docs/adr/` contains architectural decision records.

## Before exploring

Read `GLOSSARY.md` and any ADRs relevant to the work.

If these files do not exist, proceed silently. Domain modeling creates
them when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a concept is missing, reconsider the term or note the gap for domain modeling.

## Decisions

If a proposal contradicts an ADR, identify the ADR and explain why
the decision needs reconsideration.
